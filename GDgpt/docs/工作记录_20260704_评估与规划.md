## 1. 项目背景

**GDgpt** 是一个**精准肿瘤学分子肿瘤委员会（MTB, Molecular Tumor Board）会前准备辅助系统**，基于 [MDTeamGPT](https://github.com/KaiChenNJ/MDTeamGPT) 框架 fork 改造。

- **核心构成**：基于 PrimeKG 子图的 Neo4j "Task KG"（10,133 节点 / 87,838 边 / 20 种疾病，主要是癌症）+ 7 角色 LLM 专家协同（LangGraph 编排）。
- **目标场景**：肿瘤科住院医生 / 遗传咨询师在 MTB 会议前一天，为复杂病例准备**可追溯、结构化**的"基因-疾病-通路-药物"机制解释报告。
- **声称的差异化价值**：对比 GPT-4o 直答 —— 可追溯到 KG 边 + 低幻觉率 + 明确区分"图谱事实"与"LLM 推测"。
- **技术栈**：LangGraph（工作流）/ LangChain + OpenAI 兼容接口（LLM）/ Neo4j（KG）/ FAISS（向量检索）/ Streamlit（界面）。
- **历史脉络**：2026-03 通用 KGQA → 2026-04-17 导师反馈后重定位为 MTB 场景 → 文档升级到 v2.0/v2.1（详见 `docs/DECISION_LOG.md`）。

### 2026-07-13（P1-2）—— LLM-judge评估（诚实记录：GDgpt全面低分，但这本身是重要发现）

**脚本**：`llm_judge_eval.py`（5维量表+GPT-4o盲评+随机顺序+3次投票取均值）+ `compute_kappa.py`（人工kappa计算）。

**结果（9题×3次投票）**：
| 维度 | GDgpt | GPT-4o |
| --- | :---: | :---: |
| D1 事实准确 | 1.89 | **5.0** |
| D2 完整性 | 1.74 | **5.0** |
| D3 可追溯 | 1.22 | **4.41** |
| D4 临床安全 | 1.67 | **5.0** |
| D5 连贯性 | 2.63 | **5.0** |

**GDgpt在GPT-4o评分下全面低分。诚实记录，但分析根因后这是结构性假象而非真实能力差距**：

**根因1（最重要）——Self-enhancement bias**：GPT-4o judge 评 GPT-4o 的输出，天然有偏（MT-Bench/HeaLing 2026 均提及此风险）。GPT-4o 3000+字的流畅完整答案 vs GDgpt 约300字的简洁KG-grounded答案，judge 偏好前者。

**根因2——KG证据在结构化字段里，judge看不到**：GDgpt 的证据在 `cited_edges`（JSON字段）而不在答案文本里，judge 判 D3(可追溯)=1.2 是因为答案文本没有明显引用标记——但这是评测设计问题，不是系统缺陷。GDgpt 的可追溯证明来自 `cited_edges`（已用 Traceability 指标测），与答案文本长度无关。

**根因3——KG稀疏题 GDgpt 答案极短**：如 colorectal cancer 题 GDgpt 只有 173 字（KG里该病只有A2M等少量关联边），而 GPT-4o 可以从训练记忆里讲 APC/KRAS/Wnt/MSI 等无数内容（但不可追溯）。这是 KG-grounded 系统的固有约束——它拒绝超出知识库范围编造（这正是弃权卖点）。

**论文使用策略**：
1. **不能把这个 LLM-judge 结果当 GDgpt 的效用证据**（self-enhancement bias + KG证据不可见 = 结果不可信）。
2. **可以把这个发现作为论文的 discussion/limitation 点**：LLM-judge 对 KG-grounded 系统结构性不公平，因为KG证据在结构化字段而非自然语言，呼应 AttributionBench 的发现（NLI裁判不适合KG系统）——这本身是方法学贡献点。
3. **代替方案**：找1-2个人（导师/医学生）对10道题做人工盲评（human_rating_form.md已生成）——人评时会看到问题并理解"答案短=KG稀疏=诚实"vs"答案长=GPT-4o编"这个区别，报kappa比 LLM judge 更可信。

**待做**：把 human_rating_form.md 发给1-2人填写 → compute_kappa.py 计算一致性 → 用人工kappa证明评估可信度。

### 2026-07-08 —— 深入调研"字母序检索bug"，结论：改不动（重要负面结论）+ Traceability加精确率口径

**起因**：Traceability 偏低（召回0.124/精确0.076），怀疑是 tools.py 按字母序取前k导致引用了无关边。学生要求"充分调研确保改后更好"再动手。**调研救了我们——证明这个 bug 修不动。**

**调研发现（逐步用真实数据验证）**：
1. **排序逻辑**：tools.py `ORDER BY weight DESC, gene ASC`，但 **KG 里 61708 条 ASSOCIATED_WITH 边 weight 全空**（0 非空）→ 退化成纯字母序 → 取回 ABCA3/ABCB1 等字母靠前的无关基因。
2. **A1 补weight 不可行**：kg.csv 源数据**根本无 score/weight/confidence 列**（PrimeKG 原生不带边权重）。补权重需从 Open Targets 重新拉取对齐，超出毕设范围。
3. **A2 调k 有效但有权衡**：字母序前8 金标命中 **0/20**；全取命中 **20/20** 但引入 1000+ 无关边（每病关联1000+基因）→ 精确率崩。
4. **degree 排序无效**：按"基因通路连接度"取前20，金标命中仅 0-0.20。
5. **根因（决定性证据）**：金标基因来自 **Open Targets 疾病特异性打分**（gold source="Open Targets + PrimeKG cross-validated"），但该打分**不在 KG 里**。金标基因 BRCA2/BRCA1/PALB2 在 KG 的 degree 排名是 217/54/327名，散布于1156基因中，**无任何 KG 内部信号能把它们排前**。

**决定性结论**：**无论怎么改 tools.py 排序都无法命中金标，因为选金标用的信息（Open Targets score）不在 KG 里。这不是排序bug，是"金标信息源与KG不一致"。放弃改排序。**

**认知修正**（重要）：
- Gene Recall / Traceability 绝对值低，是 **KG 与金标信息源错配**的必然结果，非系统缺陷 → 论文如实写为 limitation。
- **三支柱卖点都不依赖"检索命中金标"高**：边级可追溯靠"引用的边真实存在"(已达成)、诚实降级靠"没证据时认怂"、时间分割靠泛化。是旧"F1导向"思维误导了对低召回的焦虑。
- 关键仍是对比：Traceability 0.124 vs GPT-4o 恒为 0。

**实际改动（唯一动的代码，低风险且有用）**：`compute_system_metrics.py` 的 traceability 从单一召回口径 → **同时输出 3 个口径**：`traceability`(召回)、`traceability_precision`(精确=命中/引用)、`traceability_f1`。论文可选精确率口径（更贴合"引用证据是否可信"主张）。校验：3题重算 recall=0.124/precision=0.076/f1=0.094，均出真实数字。

### 核心成果：多评委陪审团（替代人工 kappa）
依据 Verga et al. "Replacing Judges with Juries"（arXiv:2404.18796, 2024）——用架构不同的多个评委，其一致性替代人工 inter-annotator kappa，并消除单模型自我强化偏见。

- 新建 `evaluation/multi_judge_eval.py`：3 评委（gpt-4o / **qwen-max 阿里跨家族** / gpt-4o-mini）+ order-swap 去偏（每对两序都判，两序一致才算胜）+ 评委间 Spearman + swap 一致率。
- **DMXapi 可用评委模型**：gpt-4o、gpt-4.1、qwen-max、qwen-plus、gpt-4o-mini（claude/gemini/deepseek 均 503 不可用）。

| 外部 PcQA N=20 | 4.15>2.70 ★ | 2.50>1.35 ★ | 2.03<3.33 ✗ | **2/3（两强评委一致，弱评委mini反转）** |
