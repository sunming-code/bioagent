## 三、新定位：GDgpt = 精准肿瘤学 MTB 辅助工具

### 3.1 一句话定义

> **帮助肿瘤科医生在 MTB 准备阶段，快速生成某个患者的"基因—疾病—通路—药物"机制解释报告，所有结论可追溯到知识图谱的具体边。**

### 3.2 为什么这个场景适合我

| 评估维度 | 匹配情况 |
|---------|---------|
| **现有 KG 数据** | 20 种疾病几乎全是主流癌症（breast/lung/hepatocellular/ovarian/prostate/pancreatic carcinoma 等），天然就是精准肿瘤学领域 |
| **PrimeKG 数据密度** | ASSOCIATED_WITH = 30,854 条；TARGETS = 18,392 条；TREATS = 574 条 |
| **Bridge 多跳价值** | MTB 医生天然需要 `disease → gene → pathway → drug` 链式推理 |
| **学术热点** | Nature Comm 2026 Knowledge Connector / Cancer Cell 2025 context-LLM / JCO Precision Oncology 2024 |
| **对标系统** | DeepRare (Nature 2026) / RareAgents (AAAI-26 Oral) / Knowledge Connector (Nature Commun 2026) |

### 3.3 用户画像（两个典型用户）

**用户 A：肿瘤科住院医生（Oncology Fellow）**

- 使用时刻：MTB 会议前 1 天，手上 3-5 个复杂病例需要准备
- 传统方案：手动查 OncoKB → CIViC → PubMed → ClinicalTrials，耗时 1-2 小时/例
- 新替代方案：直接问 GPT-4o → 会幻觉、来源不可追溯
- **我的系统价值**：自动生成机制草稿 + 所有结论可追溯到 KG 边 + 区分"图谱事实" vs "LLM 推测"

**用户 B：遗传咨询师**

- 使用时刻：拿到测序报告后，向医生和患者解释"这个突变意味着什么"
- 需要：同时解释基因功能、相关通路、疾病关联、可用药物
- **我的系统价值**：多角色 Agent 给出"基因视角 + 通路视角 + 药物视角"完整解释

### 3.4 7 个专家角色 → MTB 席位映射

| 系统 Agent 角色 | 对应真实 MTB 席位 |
|---------------|----------------|
| GeneCurator 基因管理员 | 分子病理学家 |
| DiseaseMechanismAnalyst 疾病机制分析师 | 临床肿瘤学家 |
| PathwayBiologist 通路生物学家 | 转化医学研究员 |
| PhenotypeMapper 表型映射员 | 临床遗传师 |
| DrugMechanismAnalyst 药物机制分析师 | 临床药师 |
| EvidenceReviewer 证据评审员 | 方法学质控 |
| HypothesisIntegrator 假设整合者 | **MTB 主席**（Lead Physician）|

→ 这与 **RareAgents（AAAI-26 Oral）** 的多 Agent MDT 架构几乎一致。

## 四、对标论文参考

我精读了以下 **8 篇核心论文**，提炼了它们的"讲故事公式"供我们借鉴：

### 4.1 最直接对标的三篇

#### ① DeepRare —— Nature 2026（清华 + 上交 + 哈佛）

- **场景**：罕见病鉴别诊断决策支持，缓解"诊断奥德赛"
- **Baseline**：15+ 种（GPT-4o / DeepSeek-V3 / Claude / Baichuan-M1 / PhenoBrain / Exomiser 等）
- **关键指标**：Recall@1/3/5 + **专家一致性**（推理链被接受率 95.4%）
- **测试集**：6,401 例多中心数据，时间分割
- **→ 我们能借鉴**："traceable reasoning" 提法 + 专家一致性指标 + 时间分割测试集

#### ② RareAgents —— AAAI-26 Oral（清华）

- **场景**：罕见病多学科会诊（MDT），用多 Agent 模拟不同专科医生协同诊断
- **架构**：和我们的 7 角色专家会诊几乎一致
- **讲故事公式**：`具体病人案例 → 单专科看不全 → 需要 MDT → 用多 Agent 自动化`
- **→ 我们能借鉴**：明确把 Agent 角色映射到真实 MTB 席位

#### ③ Knowledge Connector —— Nature Communications 2026（德国 DKFZ）

- **场景**：**MTB 决策支持系统**，面向精准肿瘤学 ← **这就是我们的主场景！**
- **用户流程**：输入多组学数据 → 识别生物标志物 → 关联外部知识库 → 生成治疗建议 → 输出给 MTB 讨论
- **评测**：21 位用户结构化调查 + 268 个真实病例（90.7% 至少获 1 条临床干预建议）
- **→ 我们能借鉴**：**MTB 就是主场景的最佳证据**；评测引入用户调研 + 案例验证

## 五、新的评测体系：从"测性能"升级为"测系统"

### 5.1 新增三个关键指标

| 维度 | 指标 | 计算方式 | 对标 DeepRare 的同类指标 |
|------|------|---------|------------------------|
| **可追溯性** | Traceability Score | 输出中能追溯到 KG 边的结论占比 | traceable reasoning |
| **忠实度** | Hallucination Rate | 不能追溯到 KG/文献的编造比例 | hallucination rate |
| **临床效用** | Utility Score (1-5) | 医生觉得报告对决策有没有用 | expert consistency |

**保留的原指标**：Gene/Pathway F1（正确性）、Bridge Hit Rate（多跳有效性）

### 5.2 三档 Baseline 矩阵

| 档位 | Baseline | 配置 | 能证明什么 |
|------|---------|------|-----------|
| **Tier A：商业最强 LLM** | GPT-4o 直答 | 裸 GPT-4o | GPT-4o 强但无追溯性+有幻觉，所以需 KG |
| | Claude-3.7 直答 | 裸 Claude | 排除模型偏差 |
| | GPT-4o + Web Search | GPT-4o + Bing | 加搜索仍不如结构化 KG |
| **Tier B：相关系统** | 单 Agent + KG | 1 个 Agent 用我们的 KG | 多 Agent 协同比单 Agent 好 |
| | RAG only | KG→文本塞给 LLM，不做 Bridge | 多跳 Bridge 比单跳 RAG 好 |
| **Tier C：专业方案** | OncoKB 手动查询 | 医生手动查 | 我们比人工快且更全 |

| Gene Recall@5 | 0.055 | 0.000 | ⚠️ 偏低，待优化实体抽取 |
