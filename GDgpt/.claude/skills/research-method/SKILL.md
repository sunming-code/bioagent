# 研究工作方法（叶文倩 / GDgpt 精准肿瘤 MTB 项目）

这是与本学生长期合作提炼出的研究方法论。做任何研究性任务前先读它，按其原则工作。
项目主记录见 `docs/工作记录_20260704_评估与规划.md`（§5 活计划 / §8 执行日志），文献见 `docs/references.bib`。

## 一、最高原则：诚实不美化（红线）

- **绝不编造或篡改数字**。宁可写真实的低分 + 好的叙事，也不写好看的假数字——后者被导师一问就穿，比低分致命一百倍。本项目历史上 `导师汇报文档_v2` 曾编造"幻觉率2% vs 60%"却没跑实验，是必须避免的反面教材。
- **结果不利也如实记录 + 诊断原因**。例如实测发现 GDgpt 幻觉率反而比 GPT-4o 高，要照实写、分析是样本小/口径问题，并标注"不当结论"，而非隐藏。
- **区分"预期/目标"与"实测"**：所有还没跑出来的数字必须标 `<待实验>` 或"预期"，绝不写成已完成结果。
- **引用必须真实**：任何文献引用前用 Crossref API 联网核实 DOI/venue（见下），核实过的标 `[VERIFIED]`，没核实的标 `[CHECK-DOI]`，绝不凭记忆写引用。历史上出现过伪造 DOI（ESMO 404）、venue 错标（PrimeKG "ICLR 2022" 实为 Nature Sci Data 2023）。

## 二、工作节奏：先调研 → 再动手 → 每步校验

1. **动手前先侦察/调研**。改核心代码或定方案前，先用真实数据验证假设。典型教训：曾想改 KG 检索排序 bug，充分调研后发现"改了也没用"（金标信息不在 KG 里），调研避免了白改一堆代码。**"做好充分调研确保改后更好"是本学生的明确要求。**
2. **大改动前先给方案，等确认再写**。尤其改核心代码 / 改数据结构 / 面向外部的操作（git push、发布）。用户偏好 ask-first；有明确选项时用 AskUserQuestion 快速对齐。
3. **每个改动后立即校验是否达到目标**，不是只看"有没有输出"，而是看"判定/结果对不对"。例：加指标后要逐条看判定是否合理；生成数据后要验证格式能和下游对上；跑实验后核对数量/内容。
4. **小步提交，commit message 写清楚**；每完成一步就存档（用户明确要"每做一步存档"）。
5. **每完成一步：§8 执行日志追加流水账 + §5 活计划勾掉/重排**。两处分工：§5 向前看（现在做什么），§8 向后看（做过什么）。
6. **探索性/改核心的大改动隔离到 feature 分支**（如 `feat/adaptive-routing`），保持 `grad` 主线稳定可汇报；成了再 merge。用户偏好这种隔离。
7. **务实对待跑不动的长实验**：gpt-4o 全流程慢（3-5分钟/题），大批量实验常跑不动。先诊断是 API 慢还是流程慢（单次调用计时），确认是流程固有开销就**降规模/换 mini/推迟**，不无限等；如实记录"受限于计算开销"（这本身是可报告的 time-to-insight 特性）。后台跑 + 定期查文件行数看进度。
8. **workflow 失败别浪费**：综合 agent 易因 schema 崩，去 transcript 捞已完成 agent 的成果（见 §三）。

## 三、文献调研的做法

- **联网核实用 Crossref REST API**（可 WebFetch，权威）：
  `https://api.crossref.org/works?query.bibliographic=<关键词>&rows=5&select=DOI,title,author,container-title,published`
  按标题/作者查，不要猜 DOI。查不到就标 unverified，绝不编。
- **多角度并行调研用 Workflow**（后台跑多个 agent，每个查一个角度）。注意：**综合/复杂 schema 的 agent 容易触发 StructuredOutput 重试超限而失败**——所以让子 agent 只做"查+结构化单条结果"，综合(synthesis)由主 agent 自己做；schema 字段尽量少、避免超长字符串。若 workflow 失败，去 transcript (`subagents/workflows/<id>/agent-*.jsonl`) 捞已完成 agent 的 StructuredOutput 成果，不浪费。
- **调研要回答"这是不是真的学术空白"**：区分 `genuine_open_gap`（可当贡献）/ `partially_addressed`（可当贡献但要精确定位增量）/ `well_studied`（只能当 limitation 或"做对"而非贡献）。
- 每篇文献记 title + venue + year + DOI，追加到 `docs/references.bib` 并标核实状态。

## 四、这个项目的研究定位（三支柱）

不追"新架构"（fork 自 MDTeamGPT、赛道拥挤，硬拼必输），而是**系统整合 + 评测方法学**贡献：
1. **边级确定性可追溯**（对标 ALCE/AttributionBench，但用 KG 边精确匹配胜过概率式 NLI 裁判）
2. **KG覆盖度驱动的选择性弃权 / 诚实降级**（对标 Selective QA，但弃权信号来自外部 KG 而非模型自身置信度）—— 最独特
3. **时间分割评测**（对标 RealTime QA，规避循环评测）

## 五、把"踩的坑"转化为论文贡献（本项目的核心策略）

数字难看时，先判断是"假的低"（口径/设置问题→合理优化）还是"真的低"（客观事实→不改数字，改'比什么'）。关键洞察：
- **检索 F1 低**是因为 KG 关联过度宽泛（每病 1000+ 基因）+ 边无权重，无法排序命中金标 → 如实写为 limitation（"over-connected KG"），**不作为独立贡献**。
  ⚠️ 曾设想"覆盖天花板分解(ceiling vs conditional recall)"当贡献，但 2026-07-09 验证发现**金标基因≈100%在KG可达**，该论证不成立、已取消——教训：这类"看似聪明的论证"必须先用数据验证再写。
- **看的是对比不是绝对值**：GDgpt Traceability 0.124 vs GPT-4o 恒为 0 才是卖点。
- 好的方法学论文常常就是"发现现有评测在 X 场景失效，提出 Y"——踩的坑就是素材。

## 五-b、已验证的结论与死结（避免重走，2026-07 更新）

这些是反复验证过的事实，别再花时间去"解决"它们：
- **幻觉率/忠实度 GDgpt 打不赢 GPT-4o**：根因是 KG 检索按字母序喂错基因（ABCA3 而非 BRCA1），GPT-4o 反而大量提真实基因。**（2026-10-08 更正）** 这**不是** KG 数据的固有属性，而是**检索截断缺陷**：线上复核显示 300 个金标基因里 290 个（96.7%）确实是该疾病的 `ASSOCIATED_WITH` 邻居，是 `DiseaseToGene` 的 `LIMIT $k`（实测 k=8，且因 NCBI/MONDO 重复源行只剩 4 个不同基因）把它们截掉了。写 limitation 时要写成"可修复的检索缺陷"。卖点仍靠**可追溯(结构性赢)+弃权(100%vs0)**。
- **字母序检索的真实边界（2026-10-08 更正）**：KG 边权重全为 0（30,854 条 `ASSOCIATED_WITH` 无一例外），所以按权重排序无用——这部分旧结论成立。但"改不动"过头了：**对已截断的 top-k 做重排确实无效**（11/15 题该池与金标零重叠），**在完整邻居集合（每病 521–1156 个基因）上先排序再截断尚未试过**，这是目前唯一没被否掉的方向（待实验，别再当死结）。
- **综合环节没丢证据**（已验证）：专家真说了具体基因时 Lead+safety 都保留。病根在上游检索，不在综合。别去改 lead prompt。
- **证据留存率 0.166**：既是 limitation（查到的证据仅1/6进final），又是 GDgpt 独有可测能力（GPT-4o 无 cited_edges 算不了）。
- **最大瓶颈=多智能体太慢**（每题 20-30 次 LLM 调用，gpt-4o 3-5 分钟/题）→ 扩样本/时间分割等大实验都跑不动。**破局=自适应复杂度路由**（MDAgents，简单题单次LLM、难题才全7角色），已隔离到 `feat/adaptive-routing` 分支待实现。

## 六-a、硕士毕业论文工作量标准（核对清单）

硕士论文不是"跑出一个结果就完"——它要求：**原创系统 + 系统性实验 + 有叙事的贡献**。每推进一步都对照这张清单判断"这步是否在建设论文"。

### 工程维度（必须全部满足）

| 要求 | GDgpt 当前状态 | 差多少 |
|---|---|---|
| 至少一个端到端原创系统 | ✅ GDgpt（7角色+Bridge+弃权+路由） | — |
| ≥2个核心技术组件（非平凑） | ✅ Bridge多跳+覆盖弃权+自适应路由 | — |
| 至少一套完整评测流水线（脚本可复现） | ✅ run_batch→extract→compute_metrics | — |
| ≥2个 baseline 对比 | ✅ GPT-4o直答 / ablation(no-Bridge/single-agent) | 补外部 benchmark baseline |
| 统计严谨性（不只是均值） | ✅ Wilcoxon+bootstrap CI | — |
| 消融实验（证明每个组件有用） | ✅ Bridge消融-87%/single-agent | 可加路由消融 |
| ≥1个外部 benchmark（防循环评测） | ❌ 尚未跑 | **P1-1 PcQA** |
| 案例分析（定性理解） | ✅ 3个案例 | — |
| 代码可重现（脚本+配置模板） | ✅ config.example.json+evaluation/脚本 | — |

### 学术叙事维度（至少 4/6 满足才够投）

| 要求 | 说明 |
|---|---|
| 问题有临床/社会动机 | ✅ MTB 准备瓶颈 + 临床安全不对称性 |
| 方法有理论/文献支撑 | ✅ MDAgents/Selective QA/ALCE/KG4Diag 对标 |
| 贡献是真正空白，非复现 | ✅ KG-edge级可追溯+KG覆盖弃权（已验是空白） |
| 有定量支持的主要贡献 | ✅ Pathway F1/BridgeHit/弃权/D3 Traceability |
| 诚实面对 limitation | ✅ 字母序问题/小样本/单backbone |
| 有 future work 延伸性 | ✅ PcQA/重排/时间分割 |

### 超越均线、争取"成果更好"的策略

以下每完成一项，论文竞争力跃升一级（按性价比排）：

1. **外部 benchmark**（PcQA，100题）→ 破"循环评测"质疑，是评审硬要求
2. **第二个 backbone**（gpt-4o-mini，成本$<1）→ 破"结果 GPT-4o 专属"质疑
3. **人工评分 kappa**（哪怕1人，N=9）→ 把 LLM-judge 从"未验证代理"升级为"验证过的代理"
4. **自适应路由完整消融**（对比 full-7role-3round vs adaptive）→ 第4个贡献实测数字
5. **PrimeKGQA 时间分割子集**（post-2021 OncoKB 关联，用 build_expected 脚本）→ 支柱3实测
6. **Streamlit demo/截图**→ 论文里图3，让不读代码的评委"看到"系统

### 什么情况下要提醒自己"工作量不够"

- 只改了 prompt、没有新指标/新实验
- 只跑内部数据集，没有外部 benchmark
- 统计检验缺失（只写均值）
- baseline 只有 LLM-only，没有组件级消融
- 论文贡献列表少于3条

遇到以上任意一条，优先补最快能做的那项（通常是外部benchmark或第二backbone），而不是继续优化已有组件。

- **目标**：毕设答辩优先；workshop 论文（ACL BioNLP / Clinical NLP / ML4H）为现实目标；顶会不追。
- **样本量**：~30 主实验 + 38 消融，对"方法学+案例深度"定位够用（NEJM AI 2024 只用 38 例）。**但必须**配对统计（Wilcoxon/McNemar + bootstrap CI）撑小样本，定位成"方法学/案例深度"而非"benchmark"。
- **发表前必补**（按性价比）：①1个公开benchmark(如MedQA)+2-3个backbone（证明非GPT-4o专属，低成本高必要）；②临床评估——若招不到医生，用 **LLM-judge 作"验证过的代理"**（GPT-4o+结构化rubric+盲评随机序）+ 哪怕1-2人(导师/医学生)评同一子集报 kappa，绝不称"替代医生"；③统计严谨性（Wilcoxon/McNemar+bootstrap，标 pilot study）。
- **三支柱现状**（2026-07）：支柱1可追溯 ✅0.124vs0；支柱2弃权 ✅100%vs0(最强)；支柱3时间分割数据难弄暂缓（需真实post-cutoff关联）。消融已证 Bridge 是核心组件。可选新增第4支柱=**自适应多智能体降本**（对标MDAgents，见 feat/adaptive-routing 分支）。

## 七、格式与语言偏好

- 中文为主，专业术语保留英文。偏好**表格**对比、分级标题、TL;DR。
- 优先级 P0>P1>P2，先毕设后论文，不过度工程，"用户看得见的功能"优先于内部重构。
- 安全：`config.json`（含 API key / Aura 密码）永不提交；git 操作前反复验证无密钥泄露。
