这是个关键问题。文档已经全部就位，但**新 agent 不会主动去读** —— 你得给它一个"第一句话"让它自己主动进入状态。

下面按**不同场景**给你准备好可以直接复制的开场咒语，照抄即可。

---

## 🎯 核心原则（先理解，再用）

> **新 agent 的记忆不在 agent 里，而在你的仓库里。**
> 你要做的只是把它"指向"仓库里的 SSOT（`AGENT_HANDOFF.md`），让它自己读完再开工。
>
> **"一句话启动"公式** = 项目一句话定位 + 指向 HANDOFF + 要求它回述 4 件事 + 等它确认后才开始。

---

## 🗣️ 场景 A：**最通用版（推荐 95% 场景用这个）**

不管是 Claude Code / Cursor / Codex CLI / Windsurf / Cline / Copilot Chat 哪家，**第一句话贴这个**：

```text
这是我的研究生毕设项目 GDgpt —— 精准肿瘤学 MTB（分子肿瘤委员会）辅助系统。
我刚从上一个 AI agent 迁移过来，请按以下步骤继承任务：

【Step 1｜读文档，建立上下文】
请严格按顺序阅读以下 5 份文件（不要读整个仓库，避免被干扰）：
  1. AGENT_HANDOFF.md            ← 交接总览（必读）
  2. docs/SCENARIO_AND_RESEARCH_PROPOSAL.md  ← MTB 场景定位权威源
  3. docs/导师汇报文档.md         ← 最近一次汇报快照
  4. PRD.md（只看第 0-5 章）      ← 当前需求规格 v2.0
  5. docs/DECISION_LOG.md         ← 重大决策 + 踩过的坑 + 待办

【Step 2｜用 4 句话向我回述，确认你真的读懂了】
  (a) 项目当前定位是什么？
  (b) 最近一次导师反馈（2026-04-17）的核心要求是什么？
  (c) 当前进行中 / 下一步 / 卡点各是什么？
  (d) 有哪些工程或研究约定是不能违反的？

【Step 3｜等我确认后，才开始新任务】
在我说"确认"之前，不要改任何代码、不要跑任何命令。

现在开始 Step 1。
```

> **为什么这样设计**：
>
> - "严格按顺序 + 不要读整个仓库" → 防止 agent 乱扫仓库浪费 token / 被 v1.x 存档章节带偏
> - "用 4 句话回述" → 强制它真读了，不是装读
> - "等我确认" → 防止它读完立刻动手改错地方

## 🛠️ 实用技巧

### ✅ 技巧 1：把开场咒语存成 Snippet

- **macOS 系统**：系统偏好设置 → 键盘 → 文本替换，加一条 `;gdgpt` → 开场咒语全文
- **Raycast / Alfred**：做个 Snippet，打 `;gdgpt` 自动展开
- 这样以后开新 agent 会话，两秒搞定

### ✅ 技巧 2：验证 agent 真的读懂了

如果它回述的 4 句话里出现这些**危险信号**，说明它**没读或乱读**，让它重新读：

| 危险信号                                 | 说明                                      |
| ---------------------------------------- | ----------------------------------------- |
| 说项目是"生物医学 QA / 基因疾病机制分析" | ❌ 还是 v1.x 旧定位，没读到 v2.0          |
| 没提 MTB / 分子肿瘤委员会                | ❌ 完全没读 SCENARIO 文档                 |
| 说主要问题是"F1=0.05 太低"               | ❌ 还是旧评测视角，没理解 v2.0 系统级指标 |
| 说 baseline 只有 "LLM only"              | ❌ 没读到 4 档 baseline 设计              |
| 想直接改代码                             | ❌ 没按 Step 3 等确认                     |

### ✅ 技巧 3：给新 agent 的"会话级偏好提醒"

在开场咒语之后、实际开工之前，加一条：

```text
另外，关于协作偏好：
- 语言：中文为主，专业术语保留英文
- 格式：喜欢表格对比、分级标题、TL;DR
- 工作节奏：ask-first，大改动前先给方案
- 小步提交：commit message 写清楚
- 诚实不美化：实验结果不好就说不好
```

## 🚨 迁移前最后一个 checklist

在关闭当前 agent、打开新 agent 之前，确认：

- [ ] **Git 已提交并推送**（3 条 commit，见上一轮总结）
- [ ] **`config.json` 已另存到密码管理器**（1Password/Bitwarden，含 API Key + Neo4j 密码）
- [ ] **Neo4j Docker 容器正在跑**（新 agent 会要连它）
- [ ] **Python venv 的依赖清单** 也已提交（`requirements.txt`）
- [ ] **开场咒语已复制到剪贴板 / 存成 Snippet**

全部 ✅ 之后，打开新 agent，粘贴场景 A 的开场咒语，你就顺滑接上了。

## 💬 如果还是担心 agent 走偏

给你一个"保险绳"：**新 agent 读完后，如果它的 4 句回述里有任何一条不准确**，你就丢这一句：

```text
你的回述有偏差（具体指出哪一句）。请重新读 AGENT_HANDOFF.md 的 "🎯 当前阶段快照" 和
docs/DECISION_LOG.md 的 §1 "2026-04 重大决策"，然后重新回述。
```

一般一次纠正就到位，不到位的 agent 你也不用考虑了 😄
